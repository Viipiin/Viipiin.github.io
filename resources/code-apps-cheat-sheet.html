overview What are Code Apps & when to choose them Source: learn.microsoft.com/power-apps/developer/code-apps/overview
Code Apps let pro-developers build Power Platform apps using any modern web stack (React/Vue/Angular/Svelte) authored in VS Code, packaged with Vite, and run inside the Power Apps player. Apps inherit Power Platform identity (Entra ID), connectors, governance (DLP, tenant policies), environments and sharing. Choose Code Apps when you need: complex UI (charts, maps, custom layouts), heavy client logic, npm libraries, true unit testing, Git workflows, or pixel-perfect design that Canvas can't easily match. Choose Canvas instead when makers need to compose with formulas. Choose Model-driven when Dataverse + standard pages are enough.

add-data-source Wire a Connector — Step by Step
1. List connectionspa connection list  — get the Connection ID for each connection; pa connector list for connector IDs
2. List datasets (if any)pa connection list-datasets --connector <id> --connection-id <id>
3. List tables / sprocspa connection list-tables --connector <id> --connection-id <id> --dataset <ds> · list-procedures --connection-id <id> --dataset <ds>
4. Add it (direct)pa app add data-source --connector <id> --connection-id <id> --dataset <ds> --table <table>
4b. Add it (connection ref)pa app add data-source --connector <id> --connection-ref <refName> --solution-id <id> — environment-portable, recommended for ALM. Get the solution ID with pa solution list
5. OutputTabular (SQL/SharePoint) → src/Services/ + src/Models/. Nontabular (Office 365, Teams) → src/generated/services/ + src/generated/models/
6. Use itImport the service and call typed methods — no boilerplate auth code
7. Schema changed?New pa app refresh data-source --name <dataSourceName> — no more delete-then-readd
// Example: add Dataverse "accounts" table (direct connection) pa app add data-source \ --connector "shared_commondataservicepowerapps" \ --connection-id "<connection-id>" \ --table "accounts" // Example: add Dataverse table directly by connector name (no connection needed) pa app add data-source --connector dataverse --table accounts // Example: add SQL stored procedure pa app add data-source \ --connector "shared_sql" \ --connection-id "<connection-id>" \ --dataset "server.database.windows.net,mydb" \ --procedure "[dbo].[GetTopOrders]" // Example: add via connection reference (portable across Dev/Test/Prod) pa app add data-source \ --connector "shared_sharepointonline" \ --connection-ref "new_sharepointconnref" \ --solution-id "<solution-id>" // Refresh after a schema change — regenerates model/service files in place pa app refresh data-source --name "accounts"

dev Local Run & Debug
  • One terminal, one command: pa app run — starts the local host (tunnel + dev server) together.
  • Open the URL labeled Local Play in the output — use the same browser profile signed into your Power Platform tenant.
  • Optional flags: --port <port>, --local-app-url <url>.
  • Hot-reload: edits to .tsx/.css apply instantly.
  • Console & network: Edge/Chrome DevTools. Network shows tunnel requests routed via localhost.
  • Stop with Ctrl + C.
  • Restart pa app run any time you switch pa auth switch.
  • Chrome/Edge block public-origin → localhost requests by default (Local Network Access). Grant the browser permission, or add allow="local-network-access" on embedding iframes.
💡 If a connector returns 401/403 locally, re-run pa auth login and restart pa app run.
deploy Build & Publish
  1. Ensure pa auth status shows the right account/environment.
  2. npm run build — Vite emits dist/.
  3. pa app push — uploads the bundle & registers a new app version. Add --solution-id <id> to add it to a solution on push.
  4. App appears in Power Apps maker portal under Apps → Code apps.
  5. Share like any Power App via the maker portal, or script it: pa app share --principal <email> --access play.
  6. For ALM, add the code app to a solution and use pipelines/PAC build tools.
  7. CI/CD: share edit access to a service principal once, then run pa app push --non-interactive from the pipeline (set PA_CLI_USE_SP_AUTH=true + client ID/secret/tenant env vars).
  8. Subsequent pa app push = new published version (auto-bumped).
🚀 First push prompts for app display name & description. Re-running push updates the existing app — no second prompt. A service principal can publish updates but can't run the first pa app init/push — a maker account creates the app once, then shares it.

ALM Solutions, Pipelines, Source
  • Add the published code app to an unmanaged solution in the maker portal.
  • Include the connection-references it depends on.
  • Export managed/unmanaged via pac solution export.
  • Use Power Platform Pipelines or Azure DevOps build tools for promotion.
  • Keep power.config.json in Git; environment IDs differ per stage.
  • Tag releases in Git matching pa app push versions.
  • Don't check in node_modules/, dist/, or .env.local.
limits Known Limitations GA
  • GA since Feb 2026, but still evolving fast — check the official limitations list before a production build.
  • Requires Premium / per-app Power Apps license (end users).
  • No Storage SAS IP restriction support — compiled assets are served publicly; use Conditional Access (block by location) instead.
  • No Power Platform Git integration.
  • No Secure Implicit Connections support yet.
  • Not supported in Power Apps for Windows (native client).
  • No PowerBIIntegration function — but can be embedded in Power BI reports via the Power Apps Visual.
  • No SharePoint forms integration.
  • A service principal can publish updates to an existing app (pa app push --non-interactive, after being shared edit access) but can't create/init a new code app — a maker account must do that first.
  • No offline mode (yet); mobile native shell APIs limited — design responsively for web.
  • Cannot directly embed in Model-driven forms (use iframe or PCF).
  • No Power Fx in code — call connectors via the SDK instead.

troubleshoot Common Errors & Fixes
"pa: command not found"npm install -g @microsoft/power-apps-cli. The old power-apps binary was removed at GA.
401 on connector calls (local)Tunnel auth expired. Stop pa app run, run pa auth login, restart.
Blank page after pushForgot base: "./" in vite.config.ts. Rebuild and push.
"PowerSDK undefined" / data calls fail on loadSDK v1.0+ needs no init — if you still have an initialize() import or a loading gate from an old project, remove it; call getContext()/services directly.
Types out of syncpa app refresh data-source --name <name> for that data source (no more delete+re-add).
"Connection reference not found"You're on the wrong env. pa auth status → switch with pa auth switch --account <user>.
"App not visible in maker portal"Push completed but you filtered Code apps off. Maker → Apps → filter "Code apps".
Slow first load in productionBundle too big. Run vite build --report, code-split heavy routes.
CORS errors locallyAlways call connectors through generated services — never raw fetch to a connector URL.
Local dev blocked / blank tunnelBrowser's Local Network Access prompt (Chrome/Edge) blocking public→localhost calls. Approve the permission prompt or check enterprise policy.
Service principal push failsThe app was never shared to the SPN. A maker must run pa app share --principal <enterprise-app-object-id> --access edit first — use the Enterprise Application object ID, not the App Registration object ID.
"Premium connector blocked"User lacks Premium licence OR DLP policy blocks the connector class.
"Solution import fails"Connection references unmapped. Map them in the solution import wizard.
HMR not refreshingCheck for syntax errors in console; restart pa app run.
license Governance Cheats
  • Maker: Premium Power Apps per-user.
  • User: Premium per-user OR per-app plan covering the published app.
  • Admin enable: Power Platform Admin Center → Settings → Code apps → On.
  • DLP: Each connector in your code app is governed by the env's DLP policy.
  • Audit: Code app activity flows through Power Platform analytics + Purview.
  • Capacity: Bundle size + connector calls count toward env quotas.
  • Sharing: Use Entra security groups for scale; avoid per-user grants.

FAQ Quick Answers
Do I need Dataverse?No. You can use SharePoint, SQL, or any connector — Dataverse is just one option.
Can I use Next.js / Remix?Code Apps target a static client bundle; SSR frameworks aren't supported. Use Vite + React/Vue/Svelte/Angular SPA mode.
Can I use Tailwind CSS?Yes — install tailwindcss, init config, import in index.css. Works seamlessly with Vite.
Call Azure Functions / APIs directly?Yes — via a custom connector wrapper. Direct fetch works for public APIs, but loses governance.
Embed in a model-driven page?Use an iframe with the code app's URL, or embed via a PCF host control.
How do I version & rollback?Each pa app push creates a new version; previous versions are retained & restorable from the maker portal.
Does it work on mobile?Yes, in the Power Apps mobile player — design responsively. Native shell APIs (camera, GPS) limited via SDK; use the device's web APIs or connectors.
Users without licenses?No run without licensing — Premium licensing applies to all runtime users, even to try the app.
Is the source code visible?The compiled JS bundle is downloaded to the client (like any web app). Keep secrets server-side or in connector auth.
Migrate from Canvas?No automatic migration. Rebuild the UI in React; reuse connectors via pa app add data-source.
